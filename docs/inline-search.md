# Inline Library search

Released in v0.12.0, inline Library search replaces the grouped popup with scoped filtering in the current view. See [the approved plan](inline-search-plan.md).

## Interaction

The search icon or `/` reveals an inline field immediately left of the search icon above 1024 CSS px. At narrower widths (including high zoom), the same field reflows into a full-width row below the tabs, preserving its value and focus. No width animation moves the tabs while typing. A query follows the main Songs, Albums, Artists and Playlists tabs. Your Recap suspends search. Opening a collection starts clear; Back restores the parent query, scroll and originating control. Within artist details, Songs and Albums search their corresponding metadata. Playlist overview matching uses displayed saved/automatic names, including localized automatic names. During a nonempty query, one result grid replaces both subdivision headings, with custom matches first and matching defaults afterward. The existing main heading reports matching/total playlists for that combined grid. Clearing restores the ordinary Default Ones / Your playlists sections and creator. No match opens or starts playing automatically.

Clicking outside the search controls collapses the field without clearing its query or filtered results. The search icon marks an active query; reopening restores the text. The collection toolbar carries the clear X directly before Filter and sort in Songs, and before the primary toolbar action in other views. It is available whether the field is expanded or collapsed; the search field/navigation no longer duplicate it. Clearing preserves the field state and Favorites/sort. Focus returns to the open input, or to the neighboring Songs filter (the search opener in other views). An explicit clear retains filtered content for a 90 ms opacity exit, then restores the collection with a 150 ms entry. Content never fades to blank; old rows are briefly inert during the exit. A changed query/view cancels a pending reset, and Reduce Motion clears immediately without dimming. Normal typing and search debounce are unchanged. Dismissal uses the completed click rather than pointer-down: its target is already fixed, while menus can measure their anchors after the field collapses. It does not clear results or steal the clicked control's focus. Tab alone does not dismiss the field. Search text-edit menus, Clear and Retry remain part of the search interaction. Clear empties the current query; explicit Close clears it and collapses the field. Escape and Android Back first clear a query, including a retained query while the field is collapsed, then close an open empty field before leaving a collection. Enter applies pending input immediately and never starts playback. Results remain ordinary rows/cards with existing actions. Filtering does not save or reorder a queue or playlist; editing maps displayed IDs to original membership positions. Query changes clear song selection to prevent invisible bulk actions.

## Matching and data ownership

Matching uses all whitespace-separated terms as literal, case-insensitive NFKC-normalized substrings. Punctuation has no query syntax and accents are not stripped. Hidden library entries are excluded; unavailable entries retain their existing disabled-play behavior. Searches inspect complete catalog/collection membership before pagination. Main-view results prioritize exact primary names, then names starting with the whole query, then names containing all terms, then matches requiring secondary metadata. Primary means song title in Songs, album title in Albums, artist name in Artists and displayed playlist name in Playlists. Whitespace is canonicalized for ranking only; matching retains the literal substring contract. The selected song sort breaks equal relevance; other views keep their existing order within ties. Playlist matches prioritize custom playlists before defaults, with name relevance inside each category; the default card renderer preserves that ranked order. Album/artist/playlist track filtering preserves collection membership order. Ranking never edits playlists or playback queues.

Rust owns native matching and keeps one normalized catalog index per Store, invalidated by track/favorite/visibility writes. Both adapters cache normalized primary names alongside searchable metadata. Rust joins matched ID/relevance pairs before sorting and paging, avoiding a per-row correlated JSON scan. Native group matching caches the two normalized label indexes and at most 128 group memberships by catalog revision. Browser preview uses a separate Web Worker index and a metadata snapshot. It checks the optional `catalog-revision` settings key before reuse; imports, favorites and visibility transactions increment that key atomically with their writes. Older storage defaults to revision zero and needs no IndexedDB schema upgrade. Metadata caches do not contain decoded audio.

`groups(kind, offset, query)` filters group labels before paging/resolving memberships. `filterTrackIds(ids, query)` preserves the supplied ID order. Paged `listTracks` uses the same matching semantics. The retired grouped-search API, command, popup and exclusive overlay behavior were removed.

React updates input immediately and debounces uncached catalog/collection query work by 160 ms. Playlist overview names are already loaded: a memoized presentation filter updates the combined grid and count in the same render as the input, with no catalog request or debounce. Scope changes, Clear, Enter and cached pages avoid another debounce. The view cache holds at most 24 result pages; the worker keeps at most 32 query results and one active index. Scope/query/options/catalog revision/membership keys and request sequences reject stale replies. Retained stale content is marked busy/inert until confirmed; delayed progress and inline errors/Retry stay beside the field. The main collection heading shows matching/total counts (for example, "3 of 69 albums"); Clear restores the ordinary total. Playlist details use their existing metadata line. A visually hidden polite status announces completed results without an extra visible caption under the field. Delayed loading uses the existing search-icon space so the result rows stay fixed. Failures retain an inline Retry outside the busy result region.

## Measurement and evidence

`scripts/benchmark-search.mjs popup|inline URL` seeds an isolated 10,000-track browser database, warms one query, then measures six new queries and six repeats. It records the input event to the next painted input update and to painted confirmed results, including debounce. Artifacts are written below `artifacts/search-benchmark-*.json`.

On this desktop with Chromium 156.0.8078.4 at 1280x900, inline p95 input feedback was 32.2 ms; p95 confirmed results were 244.8 ms and repeated-query p95 was 30.4 ms. The preserved v0.11.0 popup on the same fixture measured 27.9 ms input and 14,608.5 ms results; its grouped search repeatedly traversed catalog categories. These are small desktop engineering measurements, not physical-phone performance claims or population latency statistics. The inline measurements meet the planned 50/300 ms targets.
